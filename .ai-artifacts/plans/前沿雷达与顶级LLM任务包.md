# 前沿雷达与顶级 LLM 任务包

> 背景修订：平台已有回测、point-in-time、掩码、溯源和体检实现，但不能据此断言“工程面已扎实”或研究结论已可信。先做 T0 正确性核验与 T4 对抗审计，再讨论范式扩展；Windows QMT 未就绪时收益证据仍待验证。
> ① **因子与范式可能失效**，但不能从公开时间或几个月等待直接推出拥挤/失效；需独立时间窗证据。
> ② 额度有限的高阶 LLM 必须花在刀刃上，付费模型不是研究闭环的前置条件。
>
> 本文保留原有原则、A–E prompt 模板与 T1–T6 任务模板；新增 T0，并在末尾整合已核实的接口/边界修订与有条件的 12 个月路线。历史模板中与末尾边界冲突的措辞，以修订版为准。本次不联网、不调用付费 CLI/API、不安装 Qoder 技能。

## 第一部分：顶级 LLM 的使用原则

### 核心判断：它"不知道现在什么赚钱"

顶级 LLM 的知识是训练截止前的快照，且真正在赚钱的 edge 不会公开流传——论文/研报/仓库上能看到的范式，写出来时拥挤度就已经上来了。**向它要"现在前沿是什么"的答案，得到的是幻觉或后视镜。** 它真正不可替代的三件事：

1. **消化你喂给它的新鲜材料**（读论文/代码/讨论帖比人快几十倍）；
2. **把"范式会不会死"从感觉变成监控体系**（指标设计、判定规则）；
3. **失效发生时的归因诊断**（防止误杀蛰伏因子、防止对已死因子恋战）。

结论：**人建雷达，它当分析员**。

### 额度分配原则

- **值得花**：方法论挑刺、策略顶层设计、失效诊断、假设提炼、架构级规格设计。
- **不值得花**：节点代码改写、SQL 生成、因子公式编写、机械重构——平台 AI 辅助/QUBE 用便宜模型即可。
- **省钱三习惯**：
  1. 一次对话给足弹药（README 投资边界段 + 严谨性约定 + 问题相关数据/代码片段），避免多轮补料——每轮都会重算全部上下文 token；
  2. 要"交付物"不要"讨论"：明确要求可执行的检查清单/方案/代码，一轮拿走全部价值；
  3. 它的回答沉淀进 `docs/`，以后便宜模型直接引用——"贵的想一次、便宜的用很多次"。

### 可选接入方式：先审计与证据闭环，后考虑 QUBE 模型配置

平台支持 BYOK 独立供应商（`AI_PROVIDER` / `QUBE_*` 配置，密钥入系统凭据库）。模型接入是用户另行授权的可选配置，不是首个执行步骤，也不在本次付费调用范围。先完成 T0/审计、协议登记和无数据分支，再考虑是否用高阶模型审阅假设；工具结果有依据不等于模型解释必然正确。日常高频低难度任务无需升级模型。

## 第二部分：现成 prompt 模板

### 模板 A：研究口径审计（首个执行，最防坑）

> 附件：`docs/严谨性与工程约定.md` + `backend/services/backtest_analysis.py` + `backend/services/factor_research.py` 关键段。
>
> 我在维护一个本地量化投研平台，只做 A 股纯多头、T+1、无杠杆。附件是我系统的严谨性约定和回测/因子研究引擎关键代码。请你扮演最苛刻的量化风控，找出其中仍然存在的前视偏差、幸存者偏差、成本低估、过拟合风险——不要泛泛而谈，每一条要指出具体代码位置，并构造一个会因此虚高收益（或虚低风险）的具体场景。最后按"对研究结论的扭曲程度"排序输出修复优先级。

**产出去向**：问题转 pytest 已知答案用例（参照 `docs/审查与修复流程.md`），文档沉淀进 `docs/`。

### 模板 B：12 个月投研路线图（一次问透，不要挤牙膏）

> 附件：`docs/功能模块.md` 模块表 + 实验管理导出的近三个月策略与结果 + 如实写明资金规模与风险偏好。
>
> 请给我一份 12 个月的投研路线图：应该优先深耕哪类因子/策略、平台还缺哪些功能短板、每一步的验收标准是什么。要求：考虑我的边际时间成本，不要给我"什么都做"的方案；明确指出哪几件事不做。

### 模板 C：月度前沿雷达 → 可检验假设（核心循环）

前置：平时低成本采集原料（不做分析，只收集）——arXiv q-fin 新论文、SSRN、头部券商金工研报（华泰/国盛/东证等）、GitHub 量化新仓库、有真仓的从业者讨论。每周攒 1 小时，每月或每两周用一次顶级模型：

> 附件是我过去两周收集的量化前沿材料摘要（论文/研报/新仓库）。
> 我的平台只做 A 股纯多头，算子词表见 `docs/因子编写指南.md`。
> 请提炼出 5–10 个可检验的研究假设，要求：
> ① 能映射到我现有算子或一个小改动；
> ② 标注预期的容量与拥挤风险（越多人已经在做，分越低）；
> ③ 每个假设附明确的证伪标准。
> 按"新颖度 × 可验证性 × 容量"排序输出，不要解释性长文。

**产出去向**：假设卡片直接进 QUBE/工作流跑 IC 与样本外验证。顶级 LLM 负责假设质量，平台负责证伪，便宜模型负责执行。

### 模板 D：因子失效诊断（失效发生时的应急预案）

> 附件：失效因子的 IC 序列 + 拥挤度指标 + 同期市场状态数据。
>
> 这个因子 X 月起失效。请诊断三种可能性——
> ① 数据挖掘（本来就没有 alpha）；
> ② regime 转移（换状态了，换个用法还有效）；
> ③ 拥挤度衰竭（被套利掉了）——
> 并分别给出证据标准和对应的处置（退役/条件化保留/降权）。基于我给的 IC 时间线和状态数据判断最可能是哪种，给出可核验的证据链。

### 模板 E：范式免疫设计（组合层面，低频）

> 附件：我的策略/因子清单（含衰减半衰期、风格暴露、容量估计）。
> 请设计一个对"单一范式死亡免疫"的组合规则：按衰减速度分配权重、按 regime 做条件化持有、任何单范式失效对总组合的最大回撤贡献上限。输出可执行的再平衡规则，不要泛泛的分散化建议。

## 第三部分：从开发角度提炼的顶级 LLM 任务清单

以下任务选自本文讨论的问题（失效、拥挤、regime、雷达、诊断），过滤标准：**设计密集型、需要"想清楚规则"而非"写机械代码"**——机械实现由便宜模型/普通会话完成，顶级 LLM 负责规格设计与审查。每项列出：目标、喂给它的材料、期望产出、落点。

### T0. 正确性与证据底座（先于 T1–T6）

- **目标**：先核查标签成熟、前向收益边界、T+1、终端缺价、PIT/复权、可交易掩码、残差回归病态截面、成本与统计多重检验；不能把“文档有约定”视为实现已被证明。
- **交付**：每个核实问题都有代码位置、可复现反例、pytest 已知答案与已知边界；冻结预注册协议/数据 manifest、试验预算、最终留出选择锁和不可覆盖证据。无 QMT 只验证数学与工程，研究状态保持待验证。
- **落点**：`backend/models/research.py`、`backend/services/research_registry.py`、`research_service.py`、`research_statistics.py` 与研究测试；引擎修复按独立审计范围落地，不因本任务扩大无关改动。
- **继续门槛**：P0 正确性反例关闭、隔离数据库的离线回归通过、接口无数据/失败路径明确；真实收益必须等 Windows QMT 的数据/PIT 验收后再判断。

### T1. 因子失效预警体系（依赖 T0）

- **目标**：把"怕几个月后失效"变成可复核预警。区分持有期 IC 衰减与日历时间失效、池内相关与市场拥挤，持续检查成本后证据及分状态样本量。
- **喂给它**：`factor_research.py` 现有 IC/衰减/体检/拥挤度实现、`regime.py`、因子库数据结构。
- **期望产出**：预警指标规格书——每个指标的定义式、计算窗口、告警阈值与判定规则（"死亡判定书"模板），以及指标之间的优先级（哪个信号先触发、触发后走什么处置分支）。
- **落点**：`backend/services/factor_research.py`（体检扩展）、因子详情页/体检报告前端、`docs/` 新增预警口径文档。
- **为什么值得顶级模型**：阈值与规则的设计质量直接决定"提前离场"还是"误杀"，这是统计判断而非代码问题。

### T2. Regime 条件化有效性框架

- **目标**：因子不做"全时段有效"假设，而是标注"什么市场状态下有效"，组合回测按状态切换/降权。
- **喂给它**：`regime.py`、市场环境仪表盘的数据口径、组内因子的历史 IC 时间序列样本。
- **期望产出**：状态条件化的完整设计——状态变量选型（不要过拟合的状态定义）、因子×状态有效性矩阵的估计方法（样本量小的处理）、切换与降权的交易规则（含 T+1 约束下切换的可行性）。
- **落点**：`backend/services/regime.py` + 组合回测层 + 因子库元数据加"分状态有效性"字段。
- **为什么值得顶级模型**：状态定义本身极易变成另一种过拟合，需要它把关设计。

### T3. 前沿雷达 QUBE 技能（假设卡片流水线）

- **目标**：把模板 C 固化为 QUBE 内置技能：研究员粘贴采集摘要 → 技能产出标准化假设卡片（假设/映射算子/证伪标准/拥挤度预估）→ 一键进工作流验证。
- **喂给它**：`qube_skills.py` / `qube_skill_repo.py` 现有技能结构与 QuantSkills 适配改写模式、`docs/因子编写指南.md` 算子词表、若干真实研报摘要样例。
- **期望产出**：技能手册全文（含卡片 JSON schema、排序规则、与现有挖掘工作流 SOP 的衔接），以及卡片到工作流/回测参数的映射约定。
- **落点**：QUBE 技能库（本地技能仓），前端假设卡片展示。
- **为什么值得顶级模型**：卡片质量与排序规则的判别力是核心价值，机械的技能接入由普通会话完成。

### T4. 周期性对抗审计（把"挑刺"制度化为流程）

- **目标**：每季度（或大改动后）用顶级 LLM 对回测引擎与研究口径做一次对抗审计，输出的问题转化为已知答案 pytest 用例，形成"审计→用例锁死"的闭环。
- **喂给它**：`docs/严谨性与工程约定.md` + 当季改动的核心服务文件 diff。
- **期望产出**：带代码位置与虚高场景的问题清单（模板 A 的升级版），外加建议新增的回归用例规格。
- **落点**：`tests/` 已知答案用例、`docs/审查与修复流程.md` 追加"对抗审计"章节。
- **为什么值得顶级模型**：发现"约定之外的隐性失真"需要最强的统计直觉。

### T5. 策略生命周期管理（退役/降权自动化）

- **目标**：每个策略入库时即写好死亡判定书（依赖 T1 的指标），实验管理系统在指标触发时自动建议退役/降权/条件化，而不是等研究员自己发现。
- **喂给它**：实验管理与策略库数据模型、`backtest_records.py`、策略版本历史机制。
- **期望产出**：生命周期状态机设计（在用/观察/蛰伏/退役四态及迁移条件）、自动处置建议的规则集、防止误杀的复核流程（模板 D 的诊断结果作为复核输入）。
- **落点**：`experiment_service.py` + 策略库 + QUBE 体检环节。
- **为什么值得顶级模型**：状态迁移阈值与"复核流程防误杀"是设计判断。

### T6. 一次性的路线规划会（B 模板的平台侧补充）

- **目标**：在 T1–T5 完成设计后，让顶级 LLM 基于已落地的能力做一次 12 个月投研路线图（模板 B），其结论反向决定下一批平台功能优先级。
- **产出去向**：沉淀为 `docs/` 或本目录下的路线图文档，作为后续普通开发会话的输入。

### 其他值得精进但不必动用顶级模型的方向

- **实盘/模拟盘跟踪看板**：每日信号 vs 实际成交（或模拟成交）的偏差追踪，量化"回测假设 vs 现实"的差距——用普通会话即可设计，这是未来真金白银前最后一道验证。
- **样本外滚动验证自动化**：工作流完成后自动做滚动前推验证，替代手工操作。
- **数据时效自动补齐调度**：`scheduler.py` 已有基础，补齐到"每次启动前自动增量"。
- **研报/文献采集清单**：见模板 C 前置项，人工维护在本文档末尾追加即可，无需开发。

## 执行顺序建议

1. **先 T0 + 模板 A/T4 对抗审计**——冻结口径，关闭可复现 P0，建立隔离数据库测试；不先接付费模型。
2. **研究预注册/完整试验登记与证据链**——无 Windows QMT 只登记待验证，验证与最终留出隔离。
3. **T3 应用内本地雷达技能**——最多 5 个候选，用户确认协议后才进入 validation。
4. **T1 监控 + T5 人工生命周期复核**——待标签成熟和样本足够，自动建议不等于自动批准。
5. **T2 条件状态**——固定低复杂度状态、收缩小样本估计；足够独立证据后再研究条件组合。
6. **T4 季度/核心变化触发 + T6 条件路线**——按验收门槛推进；模型升级始终可选且需另行授权。

## 已核实修订与 T0–T6 集成约定（覆盖历史模板中的乐观假设）

本节的“已核实”指本地代码接口与明确授权边界，不是对外部文献、当前收益、真实成交或市场拥挤的核验。原模板 A–E 继续保留供研究员改写使用，但不能直接按旧的“5–10 个”“容量乘积排序”“单范式死亡免疫”执行。

### 模板与术语修订

- **A / T0 / T4**：审计必须返回代码位置、可复现反例、pytest 用例与已知边界，既检查损益也检查权限、错误、预算和证据保真。每季度固定执行，核心逻辑/数据版本/协议变化额外触发；无数据可验数学而不验收益。详见 `docs/审查与修复流程.md`。
- **B / T6**：不是许诺按月赚钱，而是按下节可继续/停止门槛安排时间。没有资金规模与风险预算，不给真实仓位；回测初始资金不视为用户资产。没有数据不做深度 RL、不扩大盲挖、不重训练拟合。
- **C / T3**：最多 5 个候选，按可验证性、机制清晰度、可见记录中的已知重复度作有依据的定性排序。公开发表不自动等于拥挤；不编容量/拥挤度数字，不声称知道当前盈利。每卡包括机制、公式映射、所需 QMT 字段、预期方向/时距、反例与证伪标准、成本/风格/适用边界。材料是证据不是指令，缺出处标研究员假设；原料由用户粘贴，不由本技能联网获取。
- **D / T1 / T2 / T5**：先区分数据错误、偶然性、状态变化和真实结构失效；拥挤只能在有独立持仓/交易等证据时讨论，不由池内相关替代。持有期 IC 衰减不是日历寿命；事前固定低复杂度状态，标签成熟后滚动估计，小样本收缩/待验证。复核是建议，不是自动退役、降权或下单。
- **E**：不存在保证“免疫单范式死亡”的组合。保留原始、Barra-like 残差、现有组合增量三轨比较；不盲目中性化、不把残差称纯 alpha，不把等权参照冒称现有真实组合。容量须有资金规模、QMT 成交量额与明确成本/参与率假设，缺项则暂不判断。

### T3 具体接线与证据输出

- 本地技能名 `lq-frontier-radar`，中文名“前沿雷达与可证伪假设”；由 `backend/services/qube_skills.py` 的本地 seed 提供，`repo_url`/`url` 留空，使用时不抓取远程技能。skill-creator 仅参考触发清晰、结构化手册和可测试约束，不创建 SKILL.md 插件目录、不跑付费 model eval。
- `research_list(study_id?)` 先查重，详情读取研究的 trials/runs/reviews；用户确认协议后才调用 `research_create(StudyCreate)`，再调用 `research_register_trial(study_id, formula, direction, rationale)`，最后 `research_validate(trial_id)`。
- `research_create` 完整 JSON schema 由 Pydantic `StudyCreate` 生成；登记工具在 `TrialCreate` 根 schema 扁平添加 study_id，并保留 `$defs` 引用。四日期必须满足 `start_date < train_end < validation_end < end_date`，跨字段约束由模型校验，不以 JSON schema 能单独表达全部业务约束为前提。
- 协议逐项确认：codes=[]、horizon=5、top_n=20、rebalance_days=5、alpha=0.05、trial_budget=20、min_dates=60、min_stocks=30、commission_rate=0.001、slippage=0.001、stamp_tax=0.0005、initial_capital=1000000、baseline_formulas=[]、candidate_weight=0.25、monitor_window=60、review_every=20、minimum_effect=0、regime_index=000300.SH、regime_shrinkage=60。阈值/样本 floor 是预注册工程默认，非金融真理；minimum_effect 指每日成本后相对收益的最小实用增量。
- `backend/services/research_service.py::run_trial(trial_id, phase='validation')` 返回 run dict，重计算在线程中完成；QUBE handler 只固定调用 validation，不接收 phase 或批准参数，不替服务层实现统计。
- 保留 study_id/trial_id/run_id（按记录层级）、summary/primary/manifest/limitations；移除 tracks 的 returns/daily_ic 等大日序列，完整记录按 id 在研究页面查。异常转明确错误，无 QMT 返回 awaiting_data，不填伪造收益。
- 最终 holdout 释放与生命周期 review 只由前端人工执行。最终候选只人工选定一次，final 结果看过后不重置留出集；失败/无数据不解除选择锁。失败、人工调参、LLM 变体都计预算，不通过另建同题研究或临时代码实验绕过。
- `tests/test_research_qube.py` 只使用临时 fake registry/no-data run 验证 schema、handler 与手册约束；会话级 DB_PATH 隔离先于全局 conftest 初始化。静态测试不冒充真实 LLM 行为评测，也不证明收益。

## T6：12 个月有条件路线（按证据推进，不按日期强行上线）

月份是资源安排，不是必须完成的收益承诺；任何阶段缺 Windows QMT 数据或验收不达标，停留在当前阶段登记缺口，不接第二行情源。T0/T4 的 P0 未关闭时优先修正确性。用户批准 T0–T6 实现不等于批准付费调用、联网或真实交易。

| 阶段 | 研究工作与交付 | 继续门槛 | 停止/等待门槛 |
|---|---|---|---|
| 1–2 月 | 数据/PIT 完整性与低复杂度基线；等 Windows QMT，核对价格/复权/日历/参考字段 as-of、池范围、缺失与可交易状态，冻结 manifest 和协议 | P0 关闭；QMT 字段/日期/股票覆盖经核验；低复杂度基线可复跑，协议经用户确认 | QMT 未就绪、关键 PIT 缺失或来源不明则 awaiting_data；不接第二源，不编 IC/收益 |
| 3–4 月 | 成本后 OOS 三轨证伪；比较原始/Barra-like 残差/现有组合增量，登记完整 trial/run、失败和所有变体，处理重叠标签与多重检验 | 同口径基线、样本与预算齐全；事前主检验/最小实用效应、样本 floor 和成本边界可审计；达到预注册标准才提名 | 样本不足则等数据；预算耗尽、证据不支持或成本吞噬效果则停止该候选，不事后换方向或最佳状态 |
| 5–6 月 | 前端人工一次性选定最终留出并释放；通过后按固定规则进行影子跟踪，记录信号时点和成交假设 | 未窥探的最终证据达到预注册标准、无 P0；人工复核同意后进入观察/影子跟踪 | final 失败不重置留出；无真实成交数据只称影子记录，平台未实现的真实执行/偏差对账不可宣称已完成 |
| 7–9 月 | 条件状态与失效复核；固定低复杂度状态，标签成熟、足够日期和独立窗口后估计；滚动结果需小样本收缩 | 预注册监控窗口与复核间隔完成，能区分数据问题/噪声/状态变化；人工 review 留痕 | 状态样本稀疏或机制不清继续观察；独立证据否定则人工转 watch/dormant/retired，不自动交易、不靠新增状态拟合历史 |
| 10–12 月 | 多范式组合、成本/容量研究与年度复盘；解释三轨差异、基线增量、失效原因及未完成项 | 有不同机制的独立成本后证据；组合增量经另行预注册检验；有资金/风险预算及成交量额/成本假设才评估容量 | 增量不足保留简单基线；容量/风险资料缺失不报数字、不推荐仓位；真实成交未接入不把影子收益当实盘 |

### 明确不做与年度复盘

1. 不做深度 RL、不扩大盲挖、不在无数据条件下重训练拟合；数据/证据缺口优先于模型复杂度。
2. 不承诺赚钱，不从论文新颖性、模型等级、单次正 IC 或测试全绿推出当前盈利。
3. 不做无资金规模/风险预算的真实仓位建议，不把回测默认初资、影子信号或生命周期 active 当实盘许可。
4. 复盘所有失败/调参/LLM 变体及预算、P0/已知边界、未释放/已释放最终留出和后续独立时间窗；下一年只延续有证据、有机制且可审计的方向。
