# LocalQuant 投研可用性完善计划（P0–P2）

## 摸底结论（计划依据）

以研究员身份实测与代码审查后的核心事实：

1. **数据获取入口撑不起真实研究**：唯一数据源 QMT（[qmt_client.py](file:///Users/victor/Desktop/coding/localquant/backend/data/qmt_client.py)），但 [routes/data.py](file:///Users/victor/Desktop/coding/localquant/backend/routes/data.py) 的 download 端点仅支持**单标的**逐只下载——研究员要构建一个沪深300 股票池就得手点 300 次；本地缓存当前为空（0 个 parquet）、自建因子 0 条，且没有任何缓存覆盖度视图，无法知道本地有什么数据、缺哪段。
2. **回测引擎存在系统性失真**：[backtest_analysis.py](file:///Users/victor/Desktop/coding/localquant/backend/services/backtest_analysis.py) 的 `run_backtest` 仅做 `signal.shift(1) × pct_change − 换手成本`，无停牌冻结、无涨跌停不可成交、无权重归一化、买卖成本不区分（无印花税）——研究员看到的年化/夏普是高估的。
3. **中性化不可用**：市值、换手率字段被显式标记不可用（`routes/factor.py` 因子参考），`INDUSTRY_NEUTRALIZE` 算子是占位（[factor_operators.py](file:///Users/victor/Desktop/coding/localquant/backend/services/factor_operators.py) L102，实际只做截面去均值）；真正的行业+市值中性化 `factor_research.neutralize` 因为没有行业/市值数据而无法喂参。
4. **股票池有幸存者偏差**：只能用"当前"板块成分或手工列表，无历史成分快照；`StockListNode` 全市场模式是已知缺陷（[data_sources.py](file:///Users/victor/Desktop/coding/localquant/backend/plugins/builtin/data_sources.py) L302 返回板块名而非股票）。
5. **空壳功能**：多因子 IC 加权合成退化为等权（[factor_research.py](file:///Users/victor/Desktop/coding/localquant/backend/services/factor_research.py) L797）、特征工程 PCA 选项无实现、因子 version 字段恒为 1、预置因子"重算"不真算。
6. **研究效率短板**：[runner.py](file:///Users/victor/Desktop/coding/localquant/backend/engine/runner.py) 纯串行、无节点缓存（改一个下游参数就全图重跑，与 ComfyUI 的输出复用差距明显）；实验系统无参数扫描。
7. 扎实的部分不动它：约 130 个算子 + 公式/代码双模式因子、自研 IC/分层/衰减全套 + alphalens 双轨、QUBE Agent 端到端链路，这些是平台的长板。

数据源决策（已确认）：**维持 QMT 唯一源，不加降级源**。目标运行与研发环境均为 Windows（QMT 直连）；当前 Mac 仅为临时开发机，不作为使用场景设计。

## P0-A 数据可得性（QMT 单源下把数据获取做成生产力工具）

### 1. 批量下载
- `routes/data.py` 新增 `POST /api/data/download-batch`：入参为板块名/指数代码或代码列表 + 频率 + 日期区间，内部展开成分股后逐只 `download_history → get_kline → get_or_append`，以 SSE 汇报逐只进度与失败清单（复用 comfy/ws 或独立 SSE，与现有 runner SSE 模式一致），支持失败重试。
- DataManagement.vue 增加"按板块/指数一键下载"入口与进度条。

### 2. 缓存覆盖度可视化与增量补齐
- 新增 `GET /api/data/coverage`：扫描缓存输出"品种 × 起止日期 × 条数"矩阵，DataManagement 页渲染覆盖度表格，让研究员一眼知道本地有什么数据、缺哪段。
- 基于覆盖度提供"一键补齐至最新交易日"：对已缓存品种按各自末日期增量下载（复用批量下载通道与 `get_or_append` 的合并去重）。

### 3. 参考数据快照（中性化与股票池的数据地基）
落地为 `data/cache/reference/` 下的 parquet 快照，随批量下载/补齐流程自动更新：
- **指数成分历史快照**：每次下载时以当日为 as-of 日期追加 `(index_code, date, constituents)` 记录，逐步积累历史成分（QMT 无历史成分接口，用快照积累是 QMT 单源下唯一可行方案，需在 UI 明示"历史覆盖从首次快照开始"）。
- **行业分类**：从 QMT 申万板块（`get_sector_list`/`get_sector_stocks`）落 `(code, industry)` 快照。
- **股本/市值面板**：从 `get_financial` Capital 表取流通股本 → 与收盘价相乘生成流通市值面板；换手率 = amount / 流通市值。生成后把 `routes/factor.py` 中 market_cap/turnover_rate 的 `available=False` 翻正。
- **涨跌停价与停牌标记**：涨跌停价从 `get_instrument_detail`（UpStopPrice/DownStopPrice）当日快照 + 历史近似（±10%/±20%/±5% 按板归类）；停牌以 `volume==0 或当日无记录` 推断，生成可交易掩码面板 `tradable_mask`。
- `market_data.py` 新增 `load_reference_panels()` 统一装配上述面板，供回测与中性化调用。

## P0-B 研究正确性

### 1. 回测引擎去失真（`backtest_analysis.run_backtest`）
- **权重归一化**：新增 `normalize: none/long_only/dollar_neutral` 参数，long_only 时按日归一 Σw=1，杜绝"信号值当权重"导致的隐性杠杆。
- **停牌冻结**：接入 `tradable_mask`，不可交易日持仓沿用前一日权重（不调仓、不计换手成本），收益按实际价格（缺价时 0）。
- **涨跌停不可成交**：一字涨停（`low==high 且 close≥涨停价`）禁止买入开仓/加仓，一字跌停禁止卖出，当日调仓意图顺延。
- **成本区分买卖**：卖出加印花税（默认 0.05%，可配），买卖佣金分开；`plugins/builtin/backtest.py` 与 `routes/backtest.py` 两个入口的参数同步透出。
- 参考数据缺失时**降级为现状行为并在结果中打 `assumptions` 标记**（如 "无停牌数据，未处理停牌"），报告页展示，绝不静默假装处理过。

### 2. 分析对齐审查固化为回归测试
- 审查 `ic_analysis`（T 日因子 vs T→T+p 收益）与 `quantile_analysis`（T 日分组、T+1 起算收益）的前视/滞后对齐，用手工构造的已知答案小面板（5 股 × 30 日）写 pytest 用例锁住：完美预测因子 IC=1、随机因子 IC≈0、故意前视的数据能被用例抓出。
- 同样为回测引擎写已知答案用例：单票满仓买入持有 = 价格收益 − 一次成本；含停牌/一字板场景用例。
- 新建 `tests/` 目录（当前项目无测试），配 `make test`。

### 3. 中性化真正可用
- `INDUSTRY_NEUTRALIZE` 算子改为：从行业快照取分类调用 `factor_research.neutralize` 的行业哑变量回归；无行业数据时**显式报错**（提示先下载参考数据），不再静默去均值。
- `FactorNeutralizeNode`（factor_build.py）同步接入行业与市值面板，支持行业/市值/两者组合。

### 4. 股票池去幸存者偏差
- `StockPoolNode` 新增"指数成分（as-of 逐日）"模式：按日期用成分快照重建当日股票池，输出 `(date × code)` 成员掩码而非静态列表；快照不足时回退静态并打 assumption 标记。
- 修复 `StockListNode` 全市场模式（板块留空时聚合全部 A 股板块的股票并集）。
- 增加 ST/上市不足 N 天过滤选项（上市日期取自 `get_instrument_detail` 快照）。

## P1-A 空壳功能修复
- **IC 加权合成**：`multi_factor_combine` 的 ic_weighted 真实现——用传入的 return_data 计算各因子滚动窗口（默认 120 日）RankIC 均值，取绝对值归一为权重、符号对齐方向；无 return_data 时报错而非退化等权。工作流"多因子合成"节点透出窗口参数。
- **PCA**：`feature_engineering.py` 补 sklearn PCA 分支（保留方差比例参数），与 UI 已暴露的选项对齐。
- **因子版本化**：`routes/factor.py` 注册时同名因子 version 自增、保留历史行；因子详情页可查看/回滚历史版本公式。
- **预置因子重算**：本地缓存数据足够时（覆盖度检查通过）基于本地面板真算 IC 并写 `preset_factor_ic_history`；数据不足时明确返回"数据不足"而非假装完成。
- GNN 节点不投入，仅在节点描述中标注 experimental 与全连接图近似的局限。

## P1-B 研究效率
- **节点级输出缓存**（对标 ComfyUI）：`runner.py` 执行前按 `(节点类名, 参数 JSON, 上游输出内容哈希)` 计算 cache key，命中则直接加载既有 pickle 跳过执行，SSE 事件标记 `cached=true`；代码执行类节点（代码输入/公式计算）把代码文本纳入 key。提供"忽略缓存强制重跑"运行选项与缓存清理端点。
- **参数扫描**：`routes/workflow.py` 新增 sweep 运行模式——指定 `{node_id.param: [值列表]}` 做笛卡尔积，逐组合复用现有 runner 串行执行（有节点缓存后共同上游只算一次），每组合自动写入 experiments（params=组合、metrics=末端分析/回测节点指标），实验页直接用现有 `compare` 对比。前端在 RunCenter 或工作流页加 sweep 配置入口。
- 实验 `search` 的指标过滤从内存过滤下沉为 SQL（JSON1 提取），顺手项。

## P2 研究闭环
- **因子库工作台化**：自建因子注册后自动跑 `full_factor_analysis` 存指标快照（复用实验表）；因子池页面加相关性矩阵视图（复用 `factor_correlation`）辅助去冗余；因子列表按 IC/IR 排序筛选。
- **ML→回测衔接**：ML 节点预测输出从 list 改为 `(date × code)` 因子面板 DataFrame（训练输入需携带 date/code 索引，`feature_engineering` 输出同步保留索引），使 ML 预测可直接接"因子分析"与"回测"节点，形成 特征→模型→预测→分析→回测 完整链路。
- **时序交叉验证**：ML 节点的切分从单次时间顺序切分升级为 walk-forward（滚动训练窗/预测窗参数），预测面板由各折 out-of-sample 预测拼接——这同时就是滚动训练回测的基础。

## 测试计划
- pytest：回测已知答案（买入持有/停牌/一字板/成本）、IC 与分层对齐（完美因子/随机因子/前视陷阱）、中性化（行业内去均值后组内均值≈0）、节点缓存命中/失效、ic_weighted 权重方向。全部用构造的小面板 fixture，不依赖 QMT，当前开发机即可跑通。
- 集成：QMT 相关链路（批量下载、参考数据快照）在 Windows 环境联调验收；数据无关链路在开发机以构造的 parquet 缓存 fixture 端到端跑 `templates/factor_research.json` 模板工作流全绿。

## 假设与边界
- QMT 为唯一数据源、目标环境为 Windows（均已确认）；历史指数成分只能靠快照积累，早于首次快照的区间仍有幸存者偏差——在 UI 明示而非隐藏。
- QMT 直连的代码路径在开发期以接口抽象 + fixture 测试保证正确性，最终在 Windows 上联调。
- 实施顺序即优先级顺序：P0-A → P0-B → P1 → P2，各层可独立交付验收。
- 涉及节点行为变更的部分遵循既有节点 fork 保护与 run 方法调用约定。
