# 本地投研平台 (localquant) — 节点化投研工作站

## 一、核心理念

这是一个**功能完善的本地投研工作站**，由六大模块组成，以可视化工作流为自动化骨架串联全部能力。

**六大模块**：

| 模块 | 定位 | 说明 |
|------|------|------|
| **工作流编辑器** | 自动化骨架 | ComfyUI 风格节点编辑器，搭建研究管线，串联所有模块 |
| **数据探索** | 研究起点 | 交互式数据查询、全市场扫描、快速可视化，形成假设 |
| **因子研究** | 研究核心 | 因子评估全套工具（IC/分层/中性化/对比），因子库管理 |
| **策略回测** | 验证工具 | 向量化回测 + 完整绩效 Tear Sheet（参考 QuantStats） |
| **实验管理** | 研究沉淀 | 实验记录、参数追踪、多实验对比、研究日志 |
| **数据管理** | 基础设施 | QMT 数据下载、缓存管理、数据质量检查 |

**模块间的关系**：
- 数据探索、因子研究、策略回测可以**独立使用**（交互式操作，快速验证）
- 当研究流程成熟后，通过**工作流编辑器**将其编排为自动化管线
- 实验管理**贯穿所有模块**，自动记录每次操作
- 数据管理为所有模块提供底层数据支撑

**核心交互模型**：
- 交互式研究：在数据探索/因子研究/回测页面直接操作，快速验证想法
- 工作流自动化：将成熟的研究流程编排为节点管线，一键运行
- AI 辅助：修改单个节点代码/参数，或生成整条工作流
- 实验追溯：所有操作自动记录，可回溯、可对比

## 二、技术栈

| 层面 | 选型 | 理由 |
|------|------|------|
| Python 环境 | uv | 用户要求 |
| 后端 | FastAPI + Uvicorn | panda_quantflow 同选型，成熟异步框架 |
| 数据源 | xtquant (xtdata) | 用户要求，唯一数据源 |
| 数据处理 | pandas + numpy | 标准数据科学栈 |
| 技术指标 | pandas-ta | 纯 Python，150+ 指标，无 C 依赖 |
| 本地存储 | Parquet（数据缓存）+ SQLite（工作流/实验元数据） | 轻量，无需外部数据库 |
| 工作流存储 | SQLite JSON 字段 | 工作流 JSON 直接存 SQLite，无需 MongoDB |
| 大对象存储 | 本地文件系统（Parquet/Pickle） | 节点输出数据存文件，无需 GridFS |
| 前端 | React 18 + Vite + TypeScript | 现代快速 |
| 节点编辑器 | @xyflow/react (React Flow v12) | ComfyUI 风格节点编辑器，React 生态最佳选择 |
| 样式 | Tailwind CSS v4 | 精确控制 OpenCode 配色 |
| K线图表 | lightweight-charts (TradingView) | 金融图表行业标准，嵌入节点结果中 |
| 统计图表 | Recharts | React 原生，轻量 |
| 代码编辑 | Monaco Editor | 代码节点中编写 Python |
| 状态管理 | Zustand | React Flow 内部已用 Zustand，统一 |
| API 请求 | TanStack Query | 缓存 + 自动重试 |

**明确不引入**：MongoDB（本地无需）、RabbitMQ（本地无需）、Docker（本地开发无需）。

**关于为何不使用 ComfyUI 开源前端**：
- ComfyUI 前端使用 Vue 3 + LiteGraph.js（Canvas），与本项目 React 技术栈不匹配
- GPL-3.0 许可证对包含私有策略代码的投研平台不可接受
- 内置节点全部是图像生成领域（KSampler/CLIP/VAE），与金融分析完全无关，需替换 80%+ 代码
- 正处于 LiteGraph → Vue Nodes 2.0 的重大架构迁移期，fork 后维护风险极高
- React Flow（MIT）在 React 生态中是更优选择，提供画布能力，领域逻辑自行构建

**复用成熟开源库（不重复造轮子）**：

| 领域 | 库 | 许可证 | 用途 |
|------|-----|--------|------|
| 因子分析 | **Alphalens** | Apache 2.0 | IC 分析、分层回测、换手率分析全套工具 |
| 绩效分析 | **QuantStats** | Apache 2.0 | 最全面的绩效指标 + HTML Tear Sheet |
| 技术指标 | **pandas-ta** | MIT | 150+ 技术指标，纯 Python |
| 数据表格 | **AG Grid Community** | MIT | 企业级数据表格（排序/筛选/条件格式） |
| K线图表 | **Lightweight Charts** | Apache 2.0 | TradingView 出品，高性能金融图表 |
| 通用图表 | **Apache ECharts** | Apache 2.0 | 热力图/散点图/分布图等通用可视化 |
| 代码编辑 | **Monaco Editor** | MIT | VS Code 同款编辑器 |
| 统计分析 | **statsmodels** | BSD | 回归分析、中性化、统计检验 |
| 数据处理 | **pandas + numpy** | BSD | 标准数据科学栈 |
| 嵌入式DB | **DuckDB** | MIT | 嵌入式分析数据库，支持 SQL 查询本地 Parquet |

## 三、后端架构

### 3.1 插件系统（复刻 panda_quantflow 核心）

完全复刻 panda_quantflow 的 `@work_node` + `BaseWorkNode` 架构，适配本地场景：

```python
# backend/plugins/base.py
class BaseWorkNode(ABC):
    """节点抽象基类 — 所有节点必须实现三个方法"""
    @classmethod
    @abstractmethod
    def input_model(cls) -> Optional[Type[BaseModel]]: ...
    
    @classmethod
    @abstractmethod
    def output_model(cls) -> Optional[Type[BaseModel]]: ...
    
    @abstractmethod
    def run(self, input: BaseModel) -> Optional[BaseModel]: ...

# backend/plugins/registry.py
ALL_WORK_NODES: dict[str, Type[BaseWorkNode]] = {}

def work_node(name, group, type="general", box_color="black"):
    """装饰器 — 注册节点到全局注册表"""
    def decorator(cls):
        cls.__work_node_name__ = cls.__name__
        cls.__work_node_display_name__ = name
        cls.__work_node_group__ = group
        cls.__work_node_box_color__ = box_color
        ALL_WORK_NODES[cls.__name__] = cls
        return cls
    return decorator
```

**内置节点分类**（约 25-30 个）：

| 分组 | 节点 | 说明 |
|------|------|------|
| **01-数据获取** | QMT行情数据、QMT财务数据、QMT板块数据、交易日历、股票列表 | 从 xtquant 获取各类数据 |
| **02-数据处理** | 数据筛选、列选择、公式计算、合并数据、排序/过滤、代码执行 | 通用数据变换，含 Python 代码节点 |
| **03-技术指标** | MA/EMA、MACD、RSI、KDJ、BOLL、ATR、自定义公式 | pandas-ta 封装 |
| **04-因子构建** | 因子构建（公式）、因子构建（代码）、因子标准化、因子中性化 | 因子生产 |
| **05-因子分析** | IC计算、分组收益、因子相关性、因子衰减、多因子合成 | 因子检验 |
| **06-回测** | 向量化回测、回测报告、基准对比 | 策略验证 |
| **07-输出** | 保存CSV、保存图表、打印摘要 | 结果导出 |

**自定义因子**：用户可在 `data/custom_nodes/` 放置 .py 文件，用同样的 `@work_node` 装饰器注册，系统启动时动态加载。

**节点 Input/Output 模型示例**：


### 3.2 工作流执行引擎

复刻 panda_quantflow 的执行逻辑，简化存储层：

```
工作流 JSON → SQLite 存储
     ↓
用户点击运行 → FastAPI BackgroundTasks
     ↓
执行引擎：
  1. 从 SQLite 加载工作流 JSON
  2. Kahn 算法拓扑排序 → 分层执行顺序
  3. 逐层逐节点执行：
     a. 从 ALL_WORK_NODES 查找节点类
     b. 收集输入：static_input_data + 前驱节点输出（通过 link 字段映射）
     c. 创建 input_model 实例（Pydantic 类型校验）
     d. 调用 run()（线程池中执行）
     e. 保存输出到本地文件（Parquet/Pickle）
  4. 实时更新前端（SSE 推送执行状态）
```

**数据传递**：节点输出保存为本地文件，通过文件路径引用传递（避免内存爆炸）。

**工作流 JSON 结构**（兼容 panda_quantflow 格式）：

```json
{
  "name": "动量因子研究",
  "description": "...",
  "nodes": [
    {
      "uuid": "node-1",
      "name": "QMTKlineNode",           // 对应 BaseWorkNode 子类名
      "title": "获取日K线",
      "positionX": 100, "positionY": 200,
      "width": 240, "height": 180,
      "static_input_data": {"period": "1d", "start_date": "20200101"},
      "output_path": null               // 运行后填充
    }
  ],
  "links": [
    {
      "uuid": "link-1",
      "previous_node_uuid": "node-1",
      "input_field_name": "kline_data",     // 前驱节点的输出字段名
      "next_node_uuid": "node-2",
      "output_field_name": "stock_data"     // 后继节点的输入字段名
    }
  ]
}
```

### 4.2 工作流编辑器（核心）

**React Flow 配置**：
- `colorMode="dark"` 暗色模式
- `snapToGrid` + `snapGrid={[16, 16]}` 网格对齐
- `connectionMode="loose"` 宽松连接

**自定义节点组件**（ComfyUI 风格）：

```tsx
// 每种 box_color 对应不同节点类别色调
// 但整体保持 OpenCode 暗色调，不用蓝紫渐变

function WorkNode({ data, selected }: NodeProps) {
  return (
    <div className={cn("work-node", selected && "selected")}
         style={{ borderColor: data.boxColor }}>
      {/* 标题栏 — 用节点类别色做左侧色条 */}
      <div className="work-node-header" style={{ borderLeft: `3px solid ${data.boxColor}` }}>
        <span>{data.title}</span>
        <span className="work-node-status">{/* running/success/failed 图标 */}</span>
      </div>
      {/* 输入 Handle 列表 */}
      {data.inputs?.map((input, i) => (
        <div key={input.id} className="work-node-input">
          <Handle type="target" position={Position.Left} id={input.id} />
          <span>{input.label}</span>
        </div>
      ))}
      {/* 参数 Widget 区域（根据 schema 动态渲染） */}
      {data.widgets?.map(widget => (
        <NodeWidget key={widget.id} widget={widget} />
      ))}
      {/* 输出 Handle 列表 */}
      {data.outputs?.map((output, i) => (
        <div key={output.id} className="work-node-output">
          <span>{output.label}</span>
          <Handle type="source" position={Position.Right} id={output.id} />
        </div>
      ))}
    </div>
  );
}
```

- 执行日志：实时显示每个节点的运行状态和日志
- 节点输出：点击已完成节点查看输出数据（DataFrame 表格、图表）
- 图表：K线图（lightweight-charts）、IC 曲线、净值曲线等

**工作流运行交互**：
1. 点击运行 → 后端 SSE 推送执行进度
2. 画布上节点实时变色：灰色(待执行) → 橙色(执行中) → 绿色(成功) / 红色(失败)
3. 连线上显示数据流动动画
4. 点击已完成节点 → 底部面板显示输出结果

### 4.3 数据探索页（独立研究工具）

**设计目标**：让研究者快速浏览数据、形成假设，而不是“行情浏览”。

- **SQL 查询面板**：内嵌 Monaco Editor，用 DuckDB 直接查询本地 Parquet 数据，结果实时预览
- **全市场扫描**：选择日期 + 条件（如 PE<15 AND ROE>15%），快速筛选全市场股票
- **横截面分析**：选择某日某字段，展示全市场分布直方图、分位数、异常值标记
- **多股对比**：选择多只股票，叠加对比 K线/指标/财务数据
- **快速可视化**：选中数据列即可生成图表（K线/折线/散点/分布），无需配置
- **数据目录树**：按类型（行情/财务/板块）分类展示可用数据集，显示元信息（时间范围、数据量）

### 4.4 因子研究页（独立研究工具）

**设计目标**：覆盖因子从构建、评估、优化到管理的完整生命周期。

- **因子构建器**：
  - 公式模式：类 WorldQuant Alpha 表达式语法（rank/zscore/ts_mean 等算子）
  - 代码模式：Monaco Editor 编写 Python 因子代码
  - 实时预览因子值分布

- **因子评估工具集**（复用 Alphalens）：
  - IC 分析：IC 时序图、IC 均值、IC IR、RankIC、IC 衰减
  - 分层回测：按因子值分 N 组，各组收益曲线、单调性检验
  - 换手率分析：因子换手率、分组内换手率
  - 中性化：对市值/行业的中性化前后对比
  - 相关性矩阵：多因子相关性热力图

- **因子库管理**：
  - 因子注册：名称、公式/代码、分类、版本
  - 因子分类：按领域（动量/价值/质量/波动率等）
  - 因子搜索：按名称、标签、性能指标搜索
  - 因子对比：多因子并排对比 IC/分层收益/换手率

- **因子组合分析**：
  - 加权方案：等权、IC 加权、最优化加权
  - 组合级 IC 和收益分析

### 4.5 策略回测页（独立研究工具）

**设计目标**：机构级回测分析能力，参考 QuantStats + Pyfolio。

- **回测配置**：
  - 信号定义：基于因子/指标组合定义买卖信号
  - 仓位规则：等权/市值加权/自定义
  - 回测参数：起止日期、初始资金、手续费率、滑点
  - 基准选择：沪深300/中证500/自定义指数

- **绩效 Tear Sheet**（复用 QuantStats）：
  - 收益指标：年化收益、累计收益、月度收益热力图
  - 风险指标：年化波动率、最大回撤、最大回撤持续期、VaR、CVaR
  - 风险调整收益：Sharpe、Sortino、Calmar、Information Ratio
  - 交易统计：胜率、盈亏比、连续盈亏次数、利润因子
  - 滚动指标：滚动 Sharpe/Sortino/波动率/Beta

- **可视化图表**：
  - 累计收益曲线（策略 vs 基准）
  - 回撤曲线及回撤期标注
  - 月度收益热力图
  - 日收益分布直方图
  - 蒙特卡洛模拟分布图

- **交易分析**：
  - 交易明细表
  - 持仓时间分布
  - 手续费敏感性分析

### 4.6 工作流列表页

- 卡片式展示所有工作流
- 每张卡片：名称、描述、最近运行状态、节点数量、最后修改时间
- 支持从模板创建（内置常用研究模板）
- 支持导入/导出工作流 JSON

**内置工作流模板**：
1. **因子研究模板**：QMT数据 → 因子构建 → IC计算 → 分组收益 → 报告
2. **选股策略模板**：QMT数据 → 技术指标 → 信号生成 → 回测 → 绩效报告
3. **财务分析模板**：QMT财务数据 → 指标计算 → 筛选 → 排序输出
4. **多因子合成模板**：多路因子构建 → 相关性分析 → 加权合成 → 回测

### 4.7 数据管理页

**数据基础设施管理**（不是行情浏览）：
- QMT 连接状态检测（MiniQMT 是否运行）
- 数据下载管理：选择品种/周期/日期范围，触发增量/全量下载，显示进度
- 缓存状态：已缓存的数据统计（品种数、时间范围、磁盘占用）
- 数据质量检查：缺失值检测、复权一致性验证、幸存者偏差检查、数据更新状态
- 板块数据管理：行业/概念板块列表

### 4.8 实验管理页

**实验 = 任何一次研究操作**（工作流运行、因子分析、回测等），参考 MLflow 设计：
- 列表展示所有操作记录（来源模块、时间、状态、关键指标）
- 点击进入详情：完整参数、输出结果、执行日志
- **多实验对比**：选择多次运行，参数差异高亮，指标排序，收益曲线叠加
- 实验搜索：按参数范围、指标阈值、标签、时间范围搜索
- 支持给实验添加备注和标签
- 最优实验排行

### 4.9 工作台首页（Dashboard）

快速入口和研究概览：
- 快速操作卡片：新建工作流、数据探索、因子研究、运行回测
- 最近工作流（含运行状态）
- 最近实验（含关键指标）
- 数据状态摘要（QMT 连接状态、缓存数据量）

### 4.10 AI 辅助功能

通过 OpenAI 兼容 API（用户自行配置 API Key）：

**节点级 AI**：
- 在代码编辑节点中，AI 辅助生成/修改 Python 代码
- 选中节点 → "AI 优化参数" → 根据上下文建议参数

**工作流级 AI**：
- 描述研究目标 → AI 生成完整的工作流 JSON（节点 + 连线）
- 对现有工作流 → AI 分析并建议改进

**实现方式**：后端调用 LLM API，将工作流结构 + 节点 schema 作为上下文，生成代码或工作流 JSON。

## 八、风险与注意事项

1. **xtquant 仅 Windows**：用户 macOS 开发，QMT 数据层做好抽象隔离。QMT 未连接时 API 返回明确错误，前端友好提示。
2. **GPL v3 许可证**：panda_quantflow 使用 GPL v3。我们仅借鉴架构设计思路（装饰器注册、BaseWorkNode 接口模式），不直接复制其代码。所有代码从零编写。
3. **React Flow 性能**：DOM 渲染，数百节点没问题。研究场景通常 10-50 个节点，完全够用。
4. **pandas-ta 维护状态**：已停止活跃维护但功能完整稳定，150+ 指标覆盖所有常见技术分析需求。
5. **大对象存储**：节点输出 DataFrame 可能很大，使用 Parquet 文件存储 + 路径引用，避免内存问题。

## 九、被否决的方案及理由

| 方案 | 否决理由 |
|------|----------|
| Fork ComfyUI 前端 | Vue 3 + GPL-3.0 + 图像生成领域强耦合 + 架构迁移期，三重风险。React Flow 在 React 生态中更优 |
| 直接集成 panda_quantflow | GPL v3 传染 + 依赖过重（MongoDB, RabbitMQ）。取其架构精髓（@work_node + BaseWorkNode），自行实现 |
| 行情浏览/个股详情页面 | 投研平台不需要行情展示，需要的是数据探索、因子研究、回测分析等研究工具 |
| MongoDB + RabbitMQ | 本地单用户场景，SQLite + DuckDB + 文件系统足够 |
| backtrader/zipline 回测 | 过于重型，向量化回测 + QuantStats 分析对本地研究足够 |
| Electron 桌面应用 | 增加复杂度，浏览器更灵活 |
| 蓝紫渐变 AI 风格 | 用户明确禁止 |
